## API

Las rutas parten de `/api/v1/empresas/{empresaId}`. AE, GS y AU consultan con una membresía operable. Todas las operaciones son GET.

| Sufijo | Resultado |
| --- | --- |
| `/catalogos`, `/metodologias` | Listas paginadas con filtros `codigo` y `disponibleNuevos` |
| `/catalogos/{versionId}`, `/metodologias/{versionId}` | Detalle de la edición publicada |
| `/catalogos/{versionId}/elementos` | Resumen paginado con filtros `tipo`, `grupo`, `codigo` y `texto` |
| `/catalogos/{versionId}/elementos/{elementoId}` | Descripción y referencia de origen dentro de la edición solicitada |

El filtro de texto toma caracteres literales, y los filtros por código y grupo ignoran mayúsculas. Las ediciones retiradas conservan sus datos y referencias. Los borradores técnicos quedan fuera de las proyecciones de lectura. El runtime común recibe permisos de lectura sobre las proyecciones y los runtimes empresariales mantienen sus permisos por esquema.

## Publicación técnica de F1

Flyway común V9/V10 prepara el modelo y las metodologías. La versión empresarial sigue siendo V4. La carga de F1 se realiza por separado para mantener el contenido de la edición en el entorno interno. Desde la raíz del backend, generar el SQL fuera del repositorio y ejecutarlo con el migrador común después de Flyway.

```powershell
$f1Sql = Join-Path $env:TEMP 'mspi-catalogo-f1-1.sql'
python scripts/prepare-f1-catalog.py ../articles-401779_recurso_1.xlsx $f1Sql
psql -X --host $env:PGHOST --dbname $env:PGDATABASE --username mspi_common_migrator --file $f1Sql
```

El generador usa la biblioteca estándar de Python, verifica la huella y rechaza sobrescribir un archivo existente. El SQL carga y publica en una transacción. Repetir la carga con la misma edición verifica el contenido y conserva IDs, fecha de publicación y estado de retiro. Una corrección se incorpora como nueva versión por mantenimiento técnico. Las credenciales de operación se proporcionan mediante el mecanismo de conexión del entorno.

La carga se verificó dos veces con el rol migrador común en PostgreSQL 17.11 desechable. El rol de runtime consultó los 93 controles y las 23 cláusulas en ambas ejecuciones. El ID y el instante de publicación coincidieron y se comprobó el localizador del código `A 8,8`.

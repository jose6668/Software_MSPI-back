## API y permisos

Las rutas parten de `/api/v1/empresas/{empresaId}`. AE y GS pueden consultar y mutar. AU solo consulta. RA conserva sus vistas contextuales autorizadas y queda fuera de los listados generales. Las escrituras requieren CSRF.

| Método y ruta | Operación |
| --- | --- |
| GET `/procesos` y `/responsables-negocio` | Listados con `pagina`, `tamano` y filtro `estado` opcional |
| GET `/procesos/{procesoId}` y `/responsables-negocio/{responsableId}` | Detalle local, incluidos registros archivados |
| POST `/procesos` y `/responsables-negocio` | Creación activa |
| PUT sobre un detalle | Reemplazo de datos básicos de un registro activo con `revisionEsperada` |
| POST sobre el detalle con sufijo `/archivar` | Archivo con motivo y revisión vigente |

Antes de archivar un responsable, consultar `GET /procesos?responsableId={uuid}` para revisar los procesos vinculados. Se conservan sus referencias. Un vínculo nuevo exige un responsable activo. El archivo de un proceso conserva su identificador para referencias históricas. El inventario y sus dependencias llegarán en HU-014.

Un responsable representa una persona, cargo o área mediante los códigos `PERSONA`, `CARGO` y `AREA`. Esos códigos sirven al flujo actual. Un catálogo ampliable sigue pendiente. El vínculo a membresía es opcional, local y de referencia. Puede conservarse si esa membresía se revoca. El selector de cuentas autorizado sigue disponible en `/responsables` sin exponer identidades de otras empresas.

Los nombres repetidos se admiten mientras la unicidad normalizada siga pendiente. DEC-12 sobre cobertura, restauración de procesos o responsables y borrado físico quedan fuera de esta entrega. La API rechaza campos ajenos a su contrato.

## Migración y auditoría

Flyway empresarial V2 añade el catálogo y `eventos_actividad` en cada esquema. Las claves foráneas garantizan pertenencia local. Activos utiliza la unidad de trabajo empresarial con JPA y Auditoría registra actor, objeto, cambio de estado, motivo cuando aplica y correlación dentro de la misma transacción. El runtime tiene permiso para añadir eventos. La consulta administrativa general corresponde a la entrega de auditoría. [Claves foráneas en PostgreSQL](https://www.postgresql.org/docs/17/ddl-constraints.html#DDL-CONSTRAINTS-FK).

Para una empresa ya activa en V1, suspenderla y esperar que terminen las solicitudes en curso. Ejecutar `upgrade <empresa-uuid>` con las credenciales técnicas habituales. El comando serializa las migraciones, registra el intento y publica la versión 2 tras verificar el runtime. La empresa permanece suspendida hasta que AP la reactive con la API compatible. Una verificación fallida deja la versión sin publicar y permite repetir con el mismo UUID. Las empresas V1 pendientes de alta se preparan con `prepare <empresa-uuid>`. [Procedimiento técnico](../RECUPERACION-PREPARACION.md).

## Trazabilidad y alcance

ARQ-02, ARQ-08, ARQ-13, ARQ-14, AT-01 y APR-08, etapa de preparación. [Plan y rúbrica](../PLAN-HU-Y-RUBRICA.md).

Incluye wrapper Maven existente, comprobación del JDK, arranque integrado con JPA/Flyway y PostgreSQL real, CI y guía reproducible. Conserva Spring Boot 4.1.2 y Modulith 2.1.1, con versiones de dependencias y plugins gestionadas por sus BOM/parent.

Fuera de alcance: módulos funcionales (HU-002), modelo y migraciones empresariales (HU-003), aislamiento multiesquema (HU-004), autenticación funcional, API de negocio, frontend, documentación central y despliegue.

## Decisiones concretas de esta historia

- PostgreSQL `17.11-alpine`, fijado al digest `sha256:3540c0362c809df084ffac0ae69fe794515f9de92692f02178bcdce0ef0302ac`, solo para pruebas efímeras. Es una versión soportada según la [política oficial](https://www.postgresql.org/support/versioning/); la versión del entorno de uso sigue pendiente. El digest evita cambios silenciosos de imagen.
- Testcontainers gestionado por Spring Boot: `@TestConfiguration` y `@ServiceConnection`. Spring gestiona el ciclo de vida del contenedor junto con el contexto; no hay servicio PostgreSQL permanente ni puerto fijo. [Referencia oficial](https://docs.spring.io/spring-boot/reference/testing/testcontainers.html).
- Nombre/usuario de prueba ficticios y contraseña aleatoria por contenedor. Sin secretos reales, volúmenes persistentes ni reutilización de contenedores.
- JPA permanece habilitado, sin DDL Hibernate. Flyway permanece habilitado; todavía no existen migraciones de negocio y su ausencia no acredita el modelo físico.
- Maven Enforcer exige JDK 17 para impedir compilar accidentalmente con el Java 18 predeterminado. No se cambian las variables globales del equipo.
- El fallo Surefire previo se trata como resolución incompleta de caché. Se conserva su versión gestionada y se vuelve a resolver desde Maven Central, sin borrar la caché global ni omitir pruebas.

## Criterios de aceptación

- CA-01. Dado JDK 17 y acceso a Maven Central, el wrapper usa Maven 3.10.0 y `clean verify` compila y empaqueta el proyecto.
- CA-02. Dado un JDK de otra versión, Maven rechaza la construcción en `validate` con un mensaje útil.
- CA-03. Dado Docker compatible, `contextLoads` arranca la aplicación con PostgreSQL 17 real, consulta mediante JPA y valida el estado Flyway. No se sustituye PostgreSQL por H2 ni se excluye JPA.
- CA-04. Sin Docker operativo, la prueba requerida falla; no se omite ni se convierte en éxito.
- CA-05. CI en PR hacia `Develop` ejecuta el mismo `clean verify` con Java 17 y Docker, conserva reportes incluso si falla y no publica/despliega la aplicación.
- CA-06. El README explica requisitos, ejecución y resolución de los bloqueos observados sin credenciales reales.

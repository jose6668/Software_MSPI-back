# HU-029. Respaldo y restauración integral

El operador puede recuperar el registro común, los esquemas empresariales, catálogos, evaluaciones y evidencias en otro proyecto Docker. El respaldo conserva los roles PostgreSQL, los metadatos de inspección y la cuarentena de las evidencias.

La herramienta de [recuperación Docker](../RESPALDO-Y-RESTAURACION.md) genera una copia en frío y compara el inventario de evidencias de PostgreSQL con los tamaños y huellas SHA-256 del volumen. La restauración verifica el contenido antes de crear un volumen nuevo. Tras arrancar el destino se puede comprobar que los datos y archivos coinciden con la copia.

| Criterio | Comprobación |
| --- | --- |
| Recuperación aislada | Restaurar a un proyecto nuevo y usar un puerto HTTPS local distinto |
| Esquemas y catálogos | Cotejar empresas, versiones de catálogo, membresías y recuentos del inventario |
| Archivos y cuarentena | Cotejar tamaños, huellas y cuota. Descargar un archivo limpio y comprobar que el bloqueado responde 404 |
| Aislamiento | Conectar con dos roles empresariales. Cada uno accede a su esquema y recibe una denegación al consultar el otro |
| Copia inválida | Las pruebas automatizadas comprueban el rechazo de alteraciones, rutas escapadas, enlaces y entradas duplicadas |

Trazabilidad DMP-08, AIS-19, AT-12, SEC-029 y prueba P29. El ensayo mide tiempos observados en el laboratorio. Las metas de pérdida de datos y de recuperación requieren acordar frecuencia de copias y capacidad del destino.

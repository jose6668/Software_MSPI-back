# HU-006 — Contrato REST, errores y validaciones

Estado: En curso. Verificación local completa, CI pendiente.
Rama: feat/HU-006-contrato-rest.

Como consumidor de la API, quiero un contrato versionado y errores interpretables para integrar las operaciones del backend.

ARQ-10, DVAL-01/05/07/13, AT-13 y APR-07/08. [Convenciones REST](../CONTRATO-REST.md) y [rúbrica](../PLAN-HU-Y-RUBRICA.md).

Esta entrega establece la base de AT-13. El único recurso productivo consulta la versión del contrato. La integración con datos de negocio, estados pendientes, control de concurrencia persistente y cliente se comprueba con las historias que agreguen esas operaciones. Sesión y permisos empresariales corresponden a HU-007/008. El OpenAPI se mantiene como YAML explícito y los errores usan RFC 9457 con códigos de MSPI. Estas son decisiones técnicas de la entrega.

| Criterio | Evidencia local |
| --- | --- |
| CA-01. Respuesta v1 documentada por OpenAPI | GET/HEAD reales, ejemplo de respuesta y formato de error contrastados con la especificación |
| CA-02. Errores uniformes y correlacionados | 400/401/403/404/405/406/409/415/500, cabeceras HTTP y UUID del servidor |
| CA-03. Aceptar solo los campos y tipos permitidos | DTO con Bean Validation, validación de parámetros y rechazo de JSON fuera del contrato |
| CA-04. Distinguir una revisión obsoleta de un error de campos | Fixture de comando con revisión esperada y respuesta 409 |
| CA-05. Mantener los límites de seguridad | CSRF, rutas empresariales cerradas y comportamiento previo fuera de la API |
| CA-06. Completar construcción, pruebas y entrega | `clean verify`, JAR con OpenAPI, CI y PR hacia Develop |

El 6 de noviembre de 2026 se completó `clean verify` con Java 17.0.12, Maven Wrapper 3.10.0 y PostgreSQL 17.11 en Testcontainers. Pasaron **51 pruebas**, incluidas 16 de contrato HTTP, sin fallos, errores u omitidas. Se verificó que el JAR contiene el OpenAPI y que los controladores de prueba solo existen en el classpath de tests.

Las pruebas HTTP verifican el rechazo de claves duplicadas, tipos incompatibles y campos desconocidos. También confirman el formato uniforme de Spring MVC y Spring Security, la protección CSRF, el conflicto 409 y los accesos de salud anteriores. El conflicto HTTP se comprueba con una operación ficticia. No se declara validado el control de concurrencia de un recurso de negocio.
